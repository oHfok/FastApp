What stands out

Read from the data in the selected range — a starting point, not a verdict.

    Captured incidents

    When FastApp’s CPU stays high or its memory climbs, it records what was running at that moment: the busiest threads and the busiest timed operations.

    UI responsiveness

    Worst wait per minute for the window to react. Red dots are freezes over 100 ms.

    Memory

    Working set, private bytes, managed heap, and FastApp’s WebView2 processes. A line that only climbs is a leak.

    CPU & machine load

    FastApp and its WebView2 processes, as a share of one core (left), against the whole machine’s CPU and memory use (right).

    Managed heap breakdown

    Size by generation as of the last collection (left) and memory allocated per minute (right). A leak climbs in gen 2 or the large-object heap; churn shows as high allocation with a flat heap.

    Garbage collection

    Time the app was paused collecting memory per minute (left) and full collections (right).

    Threads & handles

    Both should settle. A steady rise means something is not being released.

    Operation timings

    Average and worst per minute for one operation. Dots are individual slow ones.

    Operations

    Everything the app times, over the selected range. Click a row to chart it above.

    Slow events

    Each time an operation went over its own limit, newest first.

    Sessions & startup

    Each launch, how it ended, and how long startup took. “Ended unexpectedly” means no clean exit was recorded — a crash or a killed process.
